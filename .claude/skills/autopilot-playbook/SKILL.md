# autopilot-playbook

autopilot Mod は、ターンが終わるたびに次のターンを起こす。本スキルは、起こされたターンで何をするかを定める。
上限 (時間・ターン数・進捗なし) の判定と停止は Mod が行う。

## 状態ディレクトリ

`~/.claude/state/autopilot/<リポジトリのキー>/`。絶対パスは起床プロンプトに入っている。

| ファイル | 書き手 | 中身 |
|---|---|---|
| `state.json` | Mod | 触らない |
| `contract.md` | 自分 | 目標・触ってよい範囲・完了の基準・禁止事項・上限 |
| `backlog.md` | 自分 | `- [ ]` のタスク列。各項目に出典 (目標 / issue #N / テスト失敗 等) を添える |
| `decisions.md` | 自分 | ユーザーに聞く代わりに自分で決めたこと |
| `blocked.md` | 自分 | 人間が必要なもの |
| `log.md` | 自分 | 1 項目終えるごとに 1〜3 行 |

## 開始時

1. `contract.md` の「触ってよい範囲」と「完了の基準」を、目標とリポジトリの実態から埋める。完了の基準は確かめ方 (テスト・コマンド・スクリーンショット) まで書く
2. `backlog.md` に前回分が残っていれば、今回の目標と照らして残すか消すかを決める。目標を 1〜数ターンで終わる粒度に分けて並べる
3. 最初の項目に着手する

## 1 ターンの進め方

- backlog の先頭にある未完了の項目を 1 つ取り、実装から検証まで終わらせる。検証していないものは完了にしない
- 終えたら `- [x]` にし、`log.md` に記録する
- 開発作業は普段どおり ship フローで進める。次の項目が決まっていれば `gh stack` で段を積み、前の PR のマージを待たない
- 区切りの良いところでターンを終えてよい。次のターンは Mod が起こす

## 質問・確認の代わりにすること

- 迷ったら推奨案を自分で選び、`decisions.md` に「問い / 採用した案 / 退けた案と理由」を書いて進める
- ユーザーにしか決められないもの (資格情報・費用・取り消せない操作・本番データの変更・方針の大転換) は `blocked.md` に書き、その項目は置いて別の項目へ移る
- 「〜しますか？」とテキストで聞いてターンを終えない

## 待つとき

- CI やレビューを待つ間は、他に進められる項目があればそちらを進める
- 何も無ければ `mcp__autopilot__wait` (最大 60 分) で起床を止める。待機が明けたら待っていた対象を確かめてから続ける

## 次のタスクの探索順 (backlog が空になったら)

1. `backlog.md` の未完了 (blocked でないもの)
2. `ship.sh status` の次のフェーズ (進行中のフローがあれば)
3. 自分の open PR の CI 失敗・未解決レビュー・コンフリクト (`gh pr list --author @me`、`gh pr checks`)
4. 目標に関係する GitHub issue (`gh issue list`)。ラベル `autopilot` が付いたものを優先する
5. テストの失敗・型や lint の警告・触ってよい範囲にある TODO / FIXME
6. 直近の変更の見直し (`/simplify`・`/code-review` 相当)。1 回の autopilot で 2 回まで

- 見つけたものは出典を添えて `backlog.md` に書いてから着手する
- 契約の「触ってよい範囲」の外や、目標と関係ないものは backlog に入れない。気になったものは `blocked.md` に提案として残す

## 終え方

- 探索順 1〜6 をすべて確かめても作業が無い、または残りがすべて blocked のときだけ `mcp__autopilot__stop` を呼ぶ
- 1 回目は必ず差し戻される。探索をやり直し、各ステップで何を調べ何が無かったかを `evidence` に書いて再度呼ぶ
- 停止したら、やったこと・`blocked.md` に残したこと・決定の要点を短く報告する

## してはいけないこと

- main への直接 push・force push・ブランチやファイルの大量削除・外部への投稿 (PR / issue 上のやり取りは除く)
- ゲームバランスや本番の挙動に効くデータの変更 (提案として `blocked.md` へ)
- `state.json` の編集
