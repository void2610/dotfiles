# task-contract — 自律タスクの契約確認

開放的な依頼に対し、**作業を開始する前に** 以下 4 点を AskUserQuestion で 1 回だけ確認する。
依頼文で既に明示されている項目は聞き直さない。全項目が明示済みなら確認を省略して即開始してよい。

1. **受け入れ基準**: 何をもって完了とするか。測定・確認方法まで具体化する
   (見た目の改善なら比較対象や参考例、挙動の修正なら再現手順と期待結果)
2. **可動範囲**: 触ってよいファイル/モジュール。新規ファイル作成の可否。既存実装の流用義務の有無
3. **検証手段と報告タイミング**: 1 イテレーションごとの検証方法 (screenshot / テスト / 実行 / codeexec) と、中間報告を入れる粒度
4. **上限**: イテレーション回数または時間の上限。到達したら継続せず現状を報告して判断を仰ぐ

## 進め方

- 確認後、合意内容を 4 行以内で復唱してから作業を開始する
- 作業中に契約外の変更 (可動範囲外のファイル・想定外の新規作成) が必要になったら、黙って広げず先に確認する
- 各イテレーションで契約した検証手段を実行し、検証結果 (スクリーンショット・実行ログ等) を添えて報告する。未検証のまま「完了」と言わない

## 非担当

- 計画・設計の深掘り尋問 → grill-me / grill-with-docs
- 同じ制約確認が 3 回以上繰り返される場合、その制約の CLAUDE.md / hook への恒久化をユーザーに提案する (本スキルは都度確認が役割)
